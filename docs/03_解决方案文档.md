# 03 解决方案文档

> 问题按「现象 → 排查 → 结论 → 修复/验证」记录。新问题续编号，过期结论就地更正并标注日期。

## P-1 大地图星系严重重叠（FLCompanion 类工具的通病）

- **现象**：用 FLCompanion / 商路探测器读取本 MOD 时大量星系挤在一起；最初本图也直接采用 `universe.ini` 的 `pos`，同样重叠。
- **排查**：统计 `universe.ini [system] pos` 发现 35 个星系同为 `5,12`、33 个同为 `0,14`（MOD 未维护该字段）。
- **结论**：导航图布局应以 `DATA\UNIVERSE\multiuniverse.ini` 为准（客户端 `MultiUniverse.dll` 读取该文件），其 `[sector]` 为每个星系给出独立坐标。
- **修复**：提取器改用 multiuniverse 星区坐标；`universe.ini pos` 仅作备用字段保留。
- **验证**：最终 162 个正式版星系无重叠（仅完全同格的变体做散开）。

## P-2 任务阶段变体星系（重复星系取舍）

- **现象**：同一星系存在多份（`CF01t/tk/tn…`、`CF60b/c`、`CF68b`、`CF90b`、`Ku03b`、`Bw01b`、`St02tk`、`CF14tk`、`CF18tk`、`CF20t`、`CF41`、`FP7_system` 等）。
- **排查**（证据链）：
  1. 终章 `M13\m13.ini` 大量引用变体（CF60b×126、CF90b×58、CF01t×49…）→ 剧情阶段副本；
  2. 通关后 `M13\openspm13.ini` 只解锁**普通版**的门（如 `Bw01_CF60`）→ 剧情结束回到普通版宇宙；
  3. 变体没有任何来自普通宇宙的入连接；
  4. `CF41` 与 `CF103` 的 133 个物体坐标完全一致（同一蜂巢的早期/后期副本）。
- **结论**：默认只显示正式版；排除 17 个变体 + 1 个剧情专用（`CF99`，仅能由 `Act_Forceland` 进入）。
- **排除清单（185 − 23 = 162）**：
  - 任务变体 17：`CF01t` `CF01tk` `CF01tn` `CF01tn2` `CF01ts` `CF60b` `CF60c` `CF68b` `CF90b` `Ku03b` `Bw01b` `St02tk` `CF14tk` `CF18tk` `CF20t` `CF41` `FP7_system`
  - 剧情专用 1：`CF99`（Triam，无跳跃门）
  - 另排除导航图占位 5：`sector01`–`sector05`（无系统文件）
  - 附带：`CF102` 为孤立文件（不在 universe/multiuniverse 中），属废弃数据，未纳入
- **保留的特殊区域（非重复，保留）**：

  | 星系 | 说明 |
  |---|---|
  | `St03` / `St03b` | 外戴森球 / 戴森球城市（内容不同） |
  | `St03b2` | 戴森球核心（伊卡洛斯站、蜂巢入口） |
  | `CF103` | 蜂巢内部（终章版本） |
  | `St02b` / `St02c` | 游牧者巢穴隧道 / 核心（地牢内部） |
  | `CF58` `CF53` `St03b` 等 | 游戏内无导航图（`NoNavMap.ini`），地图上以橙色圈标注 |

- **修复**：`MISSION_VARIANTS` / `STORY_ONLY` 配置；被排除的星系可通过「剧情/变体星系」开关以灰色虚线节点显示（置于正式版附近）。
- **验证**：`variants_report.txt`、`probe/mission_variants.txt`；162 个正式版星系。

## P-3 星系图与游戏内上下镜像

- **现象**：星系内行星/跳跃门位置与游戏内导航图上下颠倒。
- **排查**：最初按「y 向上」绘制（屏幕 y＝−z）。用**游戏内纽约导航图截图**核对 5 个跳跃门的格子：Colorado D2、California B6、Alaska G5、Texas G6、Magellan D7。
- **结论**：游戏内为 **x 右、z 下**（屏幕 y＝+z）。
- **修复**：`w2s/s2w/fitView/centerObject/滚轮缩放` 全部改为 y 向下。
- **验证**：上述 5 门 + Detroit B4、West Point C5、Missouri F5 的格子与截图逐一吻合。
- **备注**：FLCompanion 源码只是线索，最终以游戏内截图为准。

## P-4 网格格式错误（A–I/1–9 → A–H/1–8）

- **现象**：初版按 FLCompanion 的 `LetterPos` 逻辑画成 9×9 标签（A–I / 1–9）。
- **排查**：放大游戏内纽约导航图截图，底部只有 **A–H** 八个字母、左侧 **1–8** 八个数字；格位换算与坐标完全吻合。
- **结论**：游戏网格为 **8×8**，标签在格心。
- **修复**：`drawGrid()` 重写（9 条网格线、8 个格心标签）。
- **验证**：截图对照（`screenshots/02_system_li01.png`）。

## P-5 「防重叠松弛」移动了游戏原始坐标

- **现象**：大地图上 Li01（纽约）与 Li04 等本应相邻 1 格的星系被推开，与游戏布局不符。
- **排查**：早期为美观加入的松弛算法对所有距离 < 2.4 格的星系生效。
- **结论**：游戏坐标本身就是 1 格间距的网格布局，不应整体移动。
- **修复**：删除全局松弛，仅对**完全同格**的变体做圆周散开。
- **验证**：Li01 gx=61(=54+7)、gy=8 与 `multiuniverse.ini` 完全一致。

## P-6 星区相对位置与官方不符

- **现象**：最初按 `[3x3]` 的 x/y 直接排成上下两排，与游戏/官方银河图不一致。
- **排查**：对照**官方银河图**（`reference/官方银河图.jpg`）：Canis 右上、Sol 右、内核中、Altair 左、Sirius 左下（放射布局）。
- **修复**：`SECTOR_CELLS` 显式指定 5 个星区在 3×3 网格中的位置（内核 (1,1)、Sol (2,1)、Altair (0,1)、Canis (2,0)、Sirius (0,2)）。
- **验证**：`screenshots/01_universe.png` 与官方银河图排列一致。

## P-7 房子名称标签飘位

- **现象**：Sirius 星区的「库萨里/莱茵兰」等标签落到星区角落，不在各自星系群附近。
- **排查**：`multiuniverse.ini` 的 `label = 001251, -0.05, 0.17` 坐标是银河模型空间（且 y 方向与星系坐标不一致），不能直接当星区局部坐标用。
- **修复**：按**所属星系群质心**放置（Li→自由联盟、Br→布列塔尼亚、Ku→库萨里、Rh→莱茵兰；单标签星区用全部星系质心），并作为水印绘制在最上层。
- **验证**：截图中水印位于各自星群中心。

## P-8 信息卡缺失（三个子问题）

- **P-8a 漏掉 Resources.dll**：`ids_info` 高 16 位为 0 的引用（如 60232 造船厂介绍）全部缺失。
  → 依据 FLCompanion 源码线索 + **直接解析 `EXE\Resources.dll` 命中字符串**，确认 DLL 列表 **index 0 = Resources.dll**（不在 `freelancer.ini` 中）。修复后 11075/11171 条自带信息卡可解析。
- **P-8b `ids_info` 指向 RT_STRING 纯文本**：部分介绍不是 HTML 资源（如 499985 空间站介绍）。
  → `IdsResolver.info()` 增加 RT_STRING 回退。
- **P-8c 无自带信息卡时未回退原型**：未命名物体（造船厂、危险浮标…）不显示任何介绍。
  → 解析 `solararch.ini` 的 `ids_name/ids_info`，按 Archetype 回退（4427 条全部覆盖）。
- **剩余**：96 条 `ids_info` 在 MOD 数据中为空字符串（游戏内同样不显示），非提取缺陷。
- **验证**：CF90 99/99、CF68 15/15、St02 21/21、Bw01 40/40。

## P-9 文本乱码（两个子问题）

- **P-9a RT_STRING 中存的是 RDL XML**：如「乌托邦（CF59）」星系信息卡，被当纯文本转义后页面显示 `<?xml…><RDL>…` 源码。共 158 条。
  → `info()` 回退时识别 `<?xml` / `<RDL>`，按 RDL 解析。
- **P-9b RDL 的 XML 实体被双重转义**：`>>>警告：禁区<<<` 显示成 `&gt;&gt;&gt;警告…`。共 95 条。
  → 解析 RDL 文本时先 `html.unescape` 再转 HTML。
- **验证**：`probe/garbled_final.txt` 六类乱码检查全部为 0；CF59 实测正常。

## P-10 单机/在线数据混淆

- **现象**：不确定应采用 `universe.ini`/基础系统文件还是 `*mp`/`*sp` 变体。
- **排查**：`freelancer.ini` 中 `universe = universe\universe.ini`；`Li01.ini` 与 `Li01sp.ini` 内容一致；`*mp.ini` 为服务器用；`openspm*.ini` 为单机剧情脚本。
- **结论**：单机地图 = `universe.ini` + 基础系统文件 + `multiuniverse.ini` 布局。
- **备注**：FP7 特殊——CF01 的门 `goto = FP7_systemmp`，故自由模式保留 `FP7_systemmp` 而非剧情被毁版 `FP7_system`。

## P-11 备份递归事故（教训，务必遵守）

- **现象**：执行文档备份后本机卡死。
- **原因**：备份命令把目标目录设在源目录内部（`map docs\backup_20260911`）并整目录复制，`Copy-Item -Recurse` 开始无限递归（实测 201+ 层）。
- **处理**：用 `robocopy 空目录 <目标> /MIR` 安全清除超长路径树；原文件与磁盘无损伤。
- **规范**：备份时**先建备份目录，再逐个复制内容**（排除备份目录自身）；或把备份放到源目录之外。

## P-13 地图优化（贸易航线 / 交互）

- **贸易航线缺失**：游戏内导航图有浅蓝航线，本图初版未绘制。
  → 提取器按 `prev_ring/next_ring` 把 `TRADELANE_RING` 串成折线（含环数、终点站名），前端绘制线＋环（放大后显示环点），新增「贸易航线」图层开关与点击/悬停信息（Li01 共 10 条）。
- **悬停提示在后台标签页失效**：悬停更新依赖 `requestAnimationFrame`，后台标签页被节流。
  → 改为 `rAF` ＋ 60ms 定时兜底，直接执行命中检测。
- **密集区节点过大**：大地图 Sirius 星团节点相互重叠。
  → 节点半径随缩放自适应（`clamp((scale/10)^0.4, 0.55, 2.0)`）。
- **缺少缩放控件**：新增右下 ＋ / － / ⛶（适应窗口）按钮。

## P-14 基地市场清单与物品卡片（出售物品/装备/飞船）

- **需求**：基地卡片显示出售/收购的商品、装备与飞船；点击物品可打开其信息卡。
- **数据源**：`market_commodities.ini`（商品）、`market_misc.ini`（装备）、`market_ships.ini`（飞船包）。
- **标志位**：`marketgood` 逗号分隔后 **index 5**：`0`＝基地出售、`1`＝基地收购/非卖（飞船与装备表中基本恒为 0）。
  用曼哈顿验证：出售商品 3（水/H燃料/贵宾）、收购 5（金/MOX/铜…）、出售飞船 3（爱国者/犀牛/星象跟踪仪）——与原版纽约船商一致。
- **名称与信息卡解析**：商品/装备 → 各 `*_equip.ini` 的 `ids_name/ids_info`；飞船 → `goods.ini` 的 `package → hull → ship` 链 → `shiparch.ini` 的 `ids_name/ids_info`。
- **实现**：
  - 提取器生成 `data/markets.js`：`items`（884 个物品，883 个带信息卡）+ `bases`（425 个基地，代号引用）；
  - 前端首次打开基地卡片时按需加载；商品/装备/飞船以彩色标签块展示（装备超长滚动）；
  - **点击标签 → 物品卡片**：类型/代号、信息卡全文、出售基地与收购基地列表（可点击跳转到该基地）。
  - 修复：市场数据键为小写，而 `baseObjects` 为原始大小写 → 基地查找统一做小写归一，否则跳转失败。
